破限词（选填）
分析模型或出图上游拒绝血腥 / 成人向内容时使用；两个模型的破限内容不同，因此分成两栏
它能起多大作用，完全取决于「拒绝」发生在哪一层 —— 先看清，别指望它一定能解掉审核
· 模型自身拒答（靠指令对齐的模型，例如聊天画图模型、多模态模型）： 有机会被提示词影响 —— 这是本栏唯一真正有作用点的情况，但不保证成功。
· 扩散模型的过滤器（直连官方 NAI / 本地 SD / ComfyUI）： 模型本身不会「拒答」，起作用的是服务端或采样器旁的过滤器。措辞周旋有时有效； 但若它按标签命中名单，那看的是你的标签、不是你写的前缀 —— 这时怎么措辞都没用。 另外本地 ComfyUI / SD 通常本就没有审核，填了不会有坏处，但也没有意义。
· 平台级硬过滤（图像 API 自带的内容策略、或对出图结果再做一次的安全分类）： 基本无用 —— 请求在服务端就被拦下，模型根本轮不到，提示词怎么写都不会放行。
那为什么直连官方 NAI「不需要」这一栏？ 因为扩散模型没有「拒答」这个环节 —— 它不做语言理解，只是按你的提示词采样出图， 压根不存在「我不画这个」的判断可以被打动；官方付费订阅本身也允许成人向内容。 所以直连 NAI 时这一栏基本是多余的：万一真被拦，那是过滤器或中转站在做， 对策是改措辞或换线路，而不是「破限」。
所以本栏的准确定位是「有机会影响上游的拒答」，请当成一个可选的提示词前缀来理解。 反复尝试还可能触发上游风控，合规与账号风险由使用者自行承担。
本插件不内置任何内容，两栏为空时与未添加本功能完全相同；填写内容与用途由使用者自行把握， 对上游服务的合规与账号风险亦由使用者自行承担。
画师串
只在「直连官方 NAI / NAI 网关」时生效
为什么只有一部分人用得上 两条出图链路拿到的东西根本不同：
· 直连官方 NovelAI / NAI 网关（扩散模型）：送出去的是标签串， 画师串拼在画面 tag 之前，用来锁定整幅画的画风基调。
· 经 V.Adapter（OpenAI 格式上游）：送出去的是自然语言描述， 而且图是上游模型自己画完、把成品交回来的，并不是 NAI 那种「按你的提示词逐帧采样现画」。 往一段描述里塞画师名只会污染描述，所以这条链路会自动跳过画师串。
作用范围与请求方式
上面质量词 / 负面词 / 画风三栏的生效方式
这三栏只作用于上下文出图路线 —— 它们是发给分析模型的要求。 标记驱动路线下，提示词由剧情模型直接写在正文的 [ILLUST: …] 中，不经过此处。
分析模型每次请求都是一次全新的单轮对话，不携带历史轮次； 本页填写的内容会随每次请求完整发送，不会被后续对话稀释或覆盖。
画师串不在这三栏之内：它拼在发往出图上游的提示词里，作用方式见上一张卡片。

正文直出送的是什么
只有最新那一条角色回复的正文 —— 之前的对话、你发的消息、角色卡设定，一条都不会带过去。 酒馆里是人与 AI 的来回对话，整段塞进去既费 token，也会让生图模型分不清到底该画哪一幕。
正文直出的三条限制
① 只在上游读得懂自然语言时才成立：聊天画图模型 / OpenAI 兼容生图可以； 直连官方 NAI 不行 —— 送出形态为「标签串」时本模式会自动跳过，不报错也不出图。
② 一条回复固定一张图：不经分析就没有分镜，同一个正文让模型画 N 遍只会得到 N 张几乎一样的图， 因此「每轮上限」在本模式下不生效。
③ 图固定挂在回复末尾：不经分析就没有插入位置，正文末尾是唯一没有歧义的地方。
切到直出后，「提示词」页那些字段的去向变了
以前它们都是注入给分析模型的，现在直出模式下没有分析模型，改由生图模型直接接收：
・画风 → 拼成 【画风】… 放在正文之前（画风一致性的主要来源，强烈建议填）
・正面质量提示词 → 拼成 【画质】…，同上
・负面提示词 → 拼成 【负面提示词】…，同样放在正文之前（对聊天画图模型说「不要出现 X」偶尔会有反向提示的副作用，遇到就把这一栏清空 —— 这一栏本来就默认留空，填不填由你决定）
・破限词·分析模型 → 直出模式下不使用（没有分析模型可破）；破限词·生图上游照旧拼在最前面，现在它就是直接给生图模型的
・画师串 → 直出自动跳过（送的是自然语言，英文画师名混进散文只会污染描述）
两种模式共用同一个开关（上面「总开关」）与同一套出图设置（出图地址、尺寸、破限词·生图上游等）。

上游
NovelAI 协议服务的地址与鉴权
先看清两条链路的区别，能省掉大量困惑
· 直连官方 NovelAI / NAI 网关：真正的扩散模型现画 —— 你的提示词（标签、画师串）与尺寸步数等参数，都是直接作用于作画过程的。
· 经 V.Adapter（OpenAI 格式上游）：图是由上游模型自己画完、把成品返回给你的， 不是 NAI 那种「按你的提示词逐帧采样现画」。 因此画师串、Danbooru 画师标签这类只有扩散模型才认识的东西，在这条链路上不适用 （插件会自动跳过，不会拼进去）；画风与画面由上游决定，本插件不参与作画过程。

V站 专属密钥签名
只在密钥是 vcs_ 开头时才生效
V站 发两种密钥：通用密钥（无前缀）任何 NAI 客户端都能用；专属密钥 （vcs_ 开头）必须随请求附一个签名，否则 V站 直接 403、不降级。 插件检测到专属密钥时会自动算签名，且盐由站点下发、轮换后自动跟随 —— 所以下面两项一般情况下都不需要动。 用 NovelAI 官方或任意第三方中转时，本卡片的内容完全不生效。
